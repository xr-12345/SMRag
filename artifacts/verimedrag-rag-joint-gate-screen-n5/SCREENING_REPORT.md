# VeriMedRAG Phase 2B — N=5 Retrieval Joint-Gate 筛选报告

**范围**：DDXPlus validate 分支，245 例（49 病种 × 5 例，取自冻结 N=20 manifest 每病种前 5 例），
2 个噪声率（0.2 / 0.3）× 7 个 dynamic_rag 配置，逐病例配对，共 **3430 轮对话**。
基线 = `rank_only_w0.0`（检索权重 0，仅 rank_only，检索从不主动开门）。

## 一、运行成本与预计 N=20 时间

| 项目 | 数值 |
|------|------|
| BM25 索引构建 | 4.6 s（125,847 snippets） |
| 冷查询单次延迟 | 191.4 ms |
| 热命中延迟 | 0.002 ms |
| 缓存命中率 | 85.6 % |

## 二、哪些配置真正改变了轨迹

用「相对基线的逐轮动作变化」衡量（turn-level `chosen_action`/`report_index`/`verify_order`
与 `rank_only_w0.0` 对齐比较，统计发生变化的 case-noise 对）：

| 配置 | 改变最终动作的 case 对数 | 改变 VerifyOld 排序的 case 对数 |
|------|-------------------------|-------------------------------|
| rank_only_w0.1 | 23 / 490 | 76 / 490 |
| rank_only_w0.5 | 86 / 490 | 165 / 490 |
| rank_only_w1.0 | 129 / 490 | 206 / 490 |
| joint_gate_w0.1 | 69 / 490 | 127 / 490 |
| joint_gate_w0.5 | 131 / 490 | 212 / 490 |
| joint_gate_w1.0 | 173 / 490 | 250 / 490 |

检索信号（权重 > 0）在多达 **~35%** 的 case-noise 对里改变了策略轨迹（joint_gate_w1.0 173/490），
**不是 no-op**。其中真正「由检索打开门并触发新 VerifyOld」的规模：

| 配置 | 触发 VerifyOld 次数（0.2 / 0.3） | 触发病例数 | 触发核验真命中率 |
|------|--------------------------------|-----------|-----------------|
| joint_gate_w0.1 | 23 / 25 | 23 / 25 | 73.9 % / 60.0 % |
| joint_gate_w0.5 | 28 / 27 | 28 / 27 | 71.4 % / 59.3 % |
| joint_gate_w1.0 | 31 / 28 | 31 / 28 | 67.7 % / 60.7 % |

即：joint_gate 在每个噪声下对 ~10% 的病例真正触发了「历史门已关闭、由检索打开」的新 VerifyOld，
且这些核验 **60–74% 命中真实误报**（评估侧真值）。同时有 13–28 例「门打开但 AskNew 效用更高，
策略仍选 AskNew」——门打开从不强制核验，机制符合 Phase 2A 设计。

## 三、核验效率是否改善 —— 是（但未转化为诊断提升）

| 指标（均值） | 基线 w0.0 | joint_gate 区间 | 方向 |
|-------------|-----------|----------------|------|
| 不必要核验率 | 62.1% / 60.5% | 54.4%–57.9% | **↓ 4.6–7.1 pp（更好）** |
| 冲突解决率 | 34.5% / 37.1% | 39.0%–42.3% | **↑ 3.9–5.7 pp（更好）** |
| 过早停止率 | 5.3% / 6.9% | 4.1%–6.1% | ↓ 0.5–1.2 pp |
| 总原子问题数 | 9.39 / 9.48 | 9.37–9.58 | ≈ 持平 |

**核验效率确实改善**：joint_gate 的核验更精准（不必要率下降、冲突解决率上升），且**没有增加总问题数**
（它把一部分 AskNew 预算改道为针对性核验，而非简单叠加问题——与 Learned Gate「只加问题」的失败模式
**不同**）。

**但诊断终点未提升**（见下），这是关键的否定项。

## 四、最优冻结配置

在所有 joint_gate 配置中，**`joint_gate_w1.0`（retrieval_impact_weight=1.0）** 是唯一满足
全部 6 项硬判据（(1)–(6)）的候选：

| 指标（相对基线 w0.0） | w1.0 @ 0.2 | w1.0 @ 0.3 |
|----------------------|-----------|-----------|
| Top-1 变化 | **0.00 pp** | **0.00 pp** |
| Brier 相对变化 | −3.65 % | **−6.53 %** |
| 不必要核验率变化 | −6.29 pp | −4.58 pp |
| 冲突解决率变化 | +4.97 pp | +3.90 pp |
| 总问题数变化 | −0.008 | +0.094 |
| 触发核验 / 真命中 | 31 / 67.7 % | 28 / 60.7 % |

w0.1 / w0.5 在 0.3 噪声下 Top-1 分别 −0.82 pp / −1.22 pp（超出 0.5 pp 上限），故不作为冻结候选。
**结论：若冻结，选 `joint_gate_w1.0`。**

## 五、Phase 2B Go/No-Go 判定

**No-Go（不进入 N=20）。** 详见 `GO_NO_GO.md`。核心矛盾是第 (7) 条：

- 机制成立（(1) 满足，触发真实核验、60–74% 真命中，非 toy）；
- 不被基线支配（(2) 满足，Top-1 持平、Brier 略优、不必要率更低）；
- Top-1/Brier/不必要率/冲突率四项硬判据在 `joint_gate_w1.0` 全部通过（(3)–(6)）；
- **但 (7)「总问题增加换来明确诊断风险下降」不成立**：总问题数持平，Top-1 完全持平
  （0.00 pp），仅 Brier 在 w1.0 有 3.7–6.5% 的相对改善，且无 Top-1 佐证。

## 六、是否建议进入 N=20 —— 不建议

**理由（诚实且非「机制坏了」）**：

1. **N=5 的统计功效足以排除大效应**：Top-1 在 N=245 下的二项标准误 ≈ 2.6 pp。所有配置的
   Top-1 差异都落在 ±1.22 pp 以内（< 0.5 σ）。这意味着即使 joint_gate 有真实增益，它也只是
   < 1 pp 级别，且 N=5 已能证明「没有明显增益」。

2. **最可能的科学解释**：joint_gate 精准地找到了真正误报的报告（60–74% 真命中），但纠正这些
   误报**不改变最终诊断**——后验对这些具体错误是稳健的（其他正确证据已主导诊断，或 AskNew 路径
   已自行纠正）。因此「检索找到了错」≠「诊断变对了」。

3. **核验效率改善是真实的，但是次要终点**：不必要核验率下降、冲突解决率上升是稳定的正向信号，
   但任务的进入门槛是「明确诊断风险下降」，而这一点未被满足。

4. **这不是 Learned Gate 失败的复现**：joint_gate 不增加问题数、不被支配、且有效率收益；但它也
   **未达到进入 N=20 所需的「明确诊断增益」**。用 82,320 轮对话（12 进程 ~4.7 h）去确认一个
   N=5 已显示「无诊断增益」的假设，期望价值低。

**最终建议**：**No-Go，不进入 N=20。** 如需继续，更经济的下一步是（a）冻结 `joint_gate_w1.0`
并只在 Brier/校准维度做一次小样本复核，或（b）转向让检索信号影响 **AskNew 选题**（而非仅核验
门控）的探索，而非为验证核验门控投入完整 N=20。
